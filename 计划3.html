1. 产品定义与边界

项目名称橙子吃吃
产品定位朋友之间共同维护的共享美食地图；创建者建立一个共享清单，通过微信转发邀请朋友加入，成员都能查看并添加想吃或喜欢的店。
目标用户橙子酱、加入清单共同维护的朋友，以及通过分享链接只读浏览的访客。访客无需加入即可看地图和全部店铺，但不能新增、编辑或删除。
核心价值把分散在聊天里的餐厅推荐沉淀为朋友共同维护的地图，聚会前能快速找到大家收藏且离当前位置最近的店。
MVP 成功标准创建者能“创建清单 → 微信分享 → 朋友确认加入”；任一成员能“地图选点新增 → 全员同步看到 → 分类浏览 → 找最近 → 导航”；成员只能编辑/删除自己添加的店，创建者可以管理全部。
数据性质共享清单是“链接可见、成员可写”：拿到公开清单链接的人均可只读查看全部店铺；加入后的成员才能贡献内容。成员列表、OpenID、邀请信息仍不公开。

2. 已确认的技术决策

目标平台微信小程序；其他 uni-app 平台只保证不因平台专属代码导致基础构建失败，不作为本期验收目标。
工程模板dcloudio/uni-preset-vue#vite-ts，Vue 3 + TypeScript + Vite。
组件库@wot-ui/ui@2.3.2，使用 npm 安装并精确锁定版本，提交 package-lock.json。
样式SCSS；只维护一份业务主题入口 src/styles/theme.scss。src/uni.scss 仅放 uni-app 编译期需要的变量，避免两套变量重复维护。
数据存储微信云开发数据库 groups、members、invites、shops 四个集合，全部设为“仅管理端可读写”；小程序只能通过云函数访问。
服务端使用微信云函数实现邀请、加入、成员校验和共享店铺 CRUD；每次调用都从 cloud.getWXContext().OPENID 获取真实身份，绝不信任客户端传入的用户身份或角色。
分享使用 onShareAppMessage 分享公开清单标识与限时邀请 token；朋友打开后可直接只读浏览，确认加入后获得添加店铺权限。
地图微信原生 <map>；用 wx.chooseLocation 选点、wx.getLocation 定位、wx.openLocation 导航。
距离Haversine 公式计算两点之间的直线距离；界面必须写“直线距离”，不得描述成路线距离。
图标复用现有地图、美食和三类店铺素材；为新增“管理”Tab 创建同风格的简洁管理图标，并通过 sharp 开发脚本统一生成微信支持的 PNG。
测试纯函数使用 Vitest；工程执行 TypeScript 检查和微信小程序生产构建；平台能力使用开发者工具及真机验收。
依赖安装建议：npm install --save-exact @wot-ui/ui@2.3.2，并安装与官方模板兼容的 sass、vue-tsc、vitest、sharp。除已明确的 Wot UI 版本外，其余依赖优先沿用模板给出的兼容版本，不盲目升级整套 uni-app 依赖。

3. 外部前置准备

这些操作涉及微信后台，编码 AI 应能识别缺失项并降级完成代码，但最终真机闭环需要橙子酱完成：

  1. 准备正式微信小程序 AppID；测试号不能替代云开发与完整定位权限验收。
  2. 在微信开发者工具中开通云开发环境，取得云环境 ID。
  3. 创建 groups、members、invites、shops 四个集合，全部设置为“仅管理端可读写”，禁止小程序端直接读写。
  4. 创建并部署 groupApi、shopApi 云函数，安装云端依赖并确认云函数环境与小程序云环境一致。
  5. 在小程序后台申请并开通 getLocation、chooseLocation 所需接口权限。
  6. 配置“用户隐私保护指引”，准确说明位置信息用于显示当前位置、计算收藏店铺直线距离和地图选点。
  7. 用至少三个不同微信账号：A 创建并分享，B 加入并添加，C 不加入但能看到所有店铺且所有写操作都被拒绝。
  8. 体验版只能分享给已配置的体验成员；若希望普通朋友直接打开，必须完成小程序审核和正式发布。
配置约束：src/config/env.ts 只允许保存可公开的 CLOUD_ENV_ID 配置；不要创建 TENCENT_MAP_KEY，不要保存 AppSecret。若希望避免将环境 ID 固化，可提供示例文件与本地覆盖机制，但必须确保构建行为清晰。

5. 多人共享数据模型、邀请与权限

5.1 TypeScript 数据契约

export type MemberRole = 'owner' | 'member'
export type MemberStatus = 'active' | 'removed'
export type ShopCategory = 'restaurant' | 'cake' | 'milktea'

export interface Group {
  _id: string
  publicId: string               // 随机、稳定、可放在分享路径的公开标识
  name: string                 // 1～30 字
  ownerOpenId: string          // 仅服务端保存，禁止返回客户端
  visibility: 'public_read'    // MVP 固定：任何访客可读，只有成员可写
  status: 'active'
  createdAt: Date
  updatedAt: Date
}

export interface Member {
  _id: string                  // sha256(`${groupId}:${openId}`)，保证幂等且不暴露身份
  groupId: string
  userOpenId: string           // 仅服务端保存，禁止客户端传入
  displayName: string          // 清单内显示名，1～20 字
  role: MemberRole
  status: MemberStatus
  joinedAt: Date
  updatedAt: Date
}

export interface Invite {
  _id: string
  groupId: string
  tokenHash: string            // 数据库只保存 SHA-256 摘要
  createdByOpenId: string      // 仅服务端写入
  status: 'active' | 'revoked'
  expiresAt: Date              // 默认 7 天
  maxUses: number              // 默认 50
  usedCount: number
  createdAt: Date
}

export interface Shop {
  _id: string
  groupId: string
  name: string
  category: ShopCategory
  latitude: number             // GCJ-02
  longitude: number            // GCJ-02
  address: string
  remark?: string
  createdByOpenId: string      // 仅服务端保存，禁止返回客户端
  createdByName: string        // 创建时的显示名快照
  updatedByOpenId: string      // 仅服务端保存
  createdAt: Date
  updatedAt: Date
}

export interface ShopView {
  id: string
  name: string
  category: ShopCategory
  latitude: number
  longitude: number
  address: string
  remark?: string
  creatorName: string
  isMine: boolean
  canEdit: boolean
  canDelete: boolean
  createdAt: Date
  updatedAt: Date
}

export type PublicShopView = Omit<ShopView,
  'creatorName' | 'isMine' | 'canEdit' | 'canDelete'
>

5.2 字段、索引与并发规则

项目规则
清单名称trim 后 1～30 个字符；创建者可以修改。
公开标识publicId 由服务端生成、全局唯一且不可预测；它不是写权限凭据，只用于访客定位公开清单。
成员显示名trim 后 1～20 个字符，允许重名；只作为清单内展示，不申请微信头像昵称权限。
店铺字段名称 1～40、地址 1～120、备注不超过 200；分类限三个枚举；纬度 -90～90、经度 -180～180 且必须为有限数值。
位置一致性地址和坐标只能由同一次 chooseLocation 成组更新；地址只读，修改位置必须重新选点。
清单容量MVP 每个共享清单最多 200 家有效店铺，服务端新增时强制校验；这样地图可以展示清单内全部店铺，而不是只显示部分。
时间全部使用服务端时间；新增同时写 createdAt/updatedAt，编辑只更新白名单字段与 updatedAt。
邀请 token云函数生成至少 128 位不可预测随机值，分享路径携带明文 token，数据库只保存摘要；默认 7 天、最多 50 次使用，可由创建者撤销。
幂等Member._id = sha256(groupId + ':' + openId)；重复打开邀请或重复加入只返回已有成员。新增店铺携带客户端请求 ID，服务端防止重复写入。
索引groups(publicId) 唯一；members(groupId, userOpenId) 唯一；invites(tokenHash) 唯一；shops(groupId, updatedAt) 支持分页。
编辑冲突更新时携带 expectedUpdatedAt 做乐观校验；已被他人修改时提示刷新，不能静默覆盖。

5.3 服务端权限矩阵

操作创建者普通成员未加入用户
查看清单名称和全部店铺允许允许允许，只读
查看成员列表允许允许拒绝
新增店铺允许允许拒绝
编辑/删除自己的店铺允许允许拒绝
编辑/删除他人店铺允许拒绝拒绝
生成/撤销邀请允许拒绝拒绝
修改清单名称、移除成员允许拒绝拒绝
P0 安全要求：四个业务集合全部设为“仅管理端可读写”。公开查看也必须通过只读云函数，不能开放数据库客户端读权限。写操作从 cloud.getWXContext().OPENID 获取身份，并逐次检查“调用者是否为有效成员、目标资源是否属于该清单、角色是否允许、普通成员是否为店铺创建者”。客户端传入的 openId、role、createdBy、canEdit 一律不可信。
  • 创建清单时，必须用事务或幂等补偿同时创建 groups 文档与 owner 成员关系。
  • 加入清单必须先校验 token 摘要、有效期、撤销状态、使用次数和清单状态，再幂等创建成员。
  • 被移除成员立即失去成员列表、邀请和全部写权限；他此前添加的店铺保留，由创建者继续管理。创建者不能移除自己。
  • “失去读取权限”只指成员列表和管理信息；被移除者仍可像普通访客一样读取公开店铺。
  • 访客读取返回 PublicShopView，不包含添加者名称、成员信息和权限字段；成员读取返回 ShopView。两者都不返回任何 OpenID 或 token 摘要。
  • 新增店铺前必须明确提示：店铺名称、地址、坐标和备注会对拿到该清单链接的访客公开；不要在备注里填写个人隐私。
  • 日志不得输出完整地址、精确经纬度、OpenID、邀请 token、数据库完整文档或用户授权信息。
  • 正式数据库禁止自动写入示例店铺；新清单默认显示正常空态。

6. 页面与交互规格

6.1 管理 Tab pages/manage/manage.vue

  1. 底部原生 tabBar 固定为三个 Tab：地图 / 美食 / 管理。管理 Tab 使用新增的管理 PNG 图标，并遵循 Pink Topaz 选中态。
  2. 首次进入没有清单时，管理页引导输入“我的显示名称”和“清单名称”，创建共享清单并自动成为创建者；不得要求手机号或微信头像昵称授权。
  3. 管理页展示用户已加入的所有清单、当前身份与最近使用时间；选择后写入本地 currentGroupId，地图和美食 Tab 同步切换。
  4. currentGroupId 只用于界面状态，不能作为授权凭据；每次云函数请求仍须验证当前 OpenID 的有效成员关系。
  5. 切换清单时先清空上一清单的列表、marker、分页游标和在途请求；旧请求结果不得覆盖新清单。
  6. 同一页展示当前清单成员及 owner/member 标签。有效成员可看成员列表；只有创建者可生成/撤销邀请、修改名称和移除普通成员。
  7. 访客进入管理 Tab 时不显示成员列表，只展示清单名称、“当前为只读访客”和“加入清单后可添加店铺”入口。
  8. 创建者移除成员前二次确认；被移除成员立即失权，其已添加店铺继续保留并由创建者管理。创建者不能移除自己。
  9. MVP 不做所有权转让、解散清单、公开搜索和普通成员邀请；朋友未加入即可浏览，加入后才可添加自己的店铺。

6.2 邀请与微信分享 pages/invite/index.vue

  1. 创建者先点击“生成邀请链接”；云函数成功返回明文 token、有效期和剩余人数后，页面才显示 <button open-type="share">。因为 onShareAppMessage 不能依赖临时异步生成 token，不得在分享回调里现生成。
  2. onShareAppMessage 返回路径 /pages/invite/index?publicId=...&token=...，只携带公开清单标识和 URL 编码后的邀请 token，不携带内部 groupId、OpenID、角色或店铺数据。
  3. 朋友从聊天卡片打开后，先看到清单名称、“直接看看地图”和“加入后一起添加”两个入口；打开链接不得自动加入。
  4. 点击“直接看看地图”使用 publicId 进入只读地图和美食列表；即使邀请 token 过期或被撤销，公开清单仍可浏览。
  5. 朋友填写 1～20 字显示名称并确认加入；acceptInvite 幂等处理，重复点击或重复打开只能产生一条成员关系、只计一次使用次数。
  6. 邀请过期、撤销、用尽或伪造时，加入按钮提示“邀请无效或已过期”，但保留“只读查看地图”；加入成功后立即从内存和本地缓存清除 token，切换到该清单并进入地图。
  7. 分享链接可以被继续转发，因此不是“指定好友身份”。MVP 依靠 7 天有效期、50 人上限和创建者随时撤销控制风险；若未来需要逐人审批，再增加 pending 审批流程。

6.3 地图页 pages/index/index.vue

  1. 顶部显示当前共享清单名称、切换入口和“创建者/成员”标签；页面进入和每次 onShow 时刷新当前清单店铺。
  2. 所有用户，包括未加入的访客，都能看到当前公开清单内由所有成员添加的全部店铺，不能按创建人私下过滤；访客没有新增、编辑和删除入口。
  3. 定位是增强能力而不是使用门槛：首次进入先用非阻塞说明解释用途，由用户主动点击“获取当前位置”或“离我最近”后再调用定位；定位类型使用 gcj02。
  4. 地图默认围绕当前位置，默认缩放级别约 14；如果定位不可用，优先使用本地保存的上一次有效位置，否则使用应用内固定回退中心，并明确显示“尚未获取当前位置”。
  5. 用三类现有 PNG 生成 markers。微信 marker 的 id 使用本地数值 ID，同时维护 Map<number, string> 映射到云数据库字符串 _id。
  6. 点击 marker 后显示店铺卡片：名称、分类、地址、备注、直线距离（有定位时）和“导航前往”。成员可额外看到添加者显示名；只有 canEdit/canDelete 为真时显示管理按钮。
  7. 右下角“离我最近”按钮打开底部弹层，按直线距离升序显示。没有定位时按钮仍可点击，但弹出解释和“重新授权/重新定位”操作；没有店铺时展示空态及“去添加”。
  8. 初次载入不要自动执行 include-points，避免远距离店铺把地图缩得过小。可提供“显示全部”按钮，由用户主动触发。
  9. 云函数按页读取当前清单全部有效店铺并生成 markers；在 200 家 MVP 容量内，地图必须展示全部店铺，不能只取前 20 条或当前用户的数据。
  10. 地图上方显示简洁分类图例；所有浮层、FAB 和弹窗必须尽早在 iOS、Android 真机验证与原生 map 的叠层兼容。

6.4 美食页 pages/food/food.vue

  1. 顶部分类 Tab：全部、饭店、蛋糕店、奶茶店。切换分类后重置分页并重新查询。
  2. 顶部显示当前共享清单和切换入口。所有访客和成员都能看到完整店铺列表；成员可看到添加者显示名。只有自己添加的店铺或创建者管理任意店铺时才显示编辑/删除。
  3. 每页 PAGE_SIZE = 20，支持加载更多；展示明确的首次加载、加载更多、没有更多、空数据和加载失败状态。
  4. 有效成员显示 FAB“新增店铺”；访客不显示 FAB，并展示“加入清单后可以添加店铺”的轻提示。表单字段包括名称、分类、“在地图上选点”、只读地址、备注。
  5. wx.chooseLocation 成功后一次性回填地址和坐标；用户取消不报错、不清空已有选择。地址不允许脱离坐标单独编辑。
  6. 新增与编辑共用同一套校验和表单组件逻辑。保存期间禁用提交按钮，防止重复点击；失败保留用户输入并提供重试。
  7. 删除必须二次确认；删除期间禁用重复操作；失败时保留列表项并显示可理解的错误提示。
  8. 新增时由服务端绑定当前清单和当前成员；客户端不得提交创建者身份。新增、编辑或删除成功后更新列表，其他成员刷新或重新进入时必须看到同步结果。

8. 云函数 API、数据访问与分页策略

  • src/services/group.ts 和 src/services/shop.ts 是页面调用云函数的唯一入口；小程序端禁止出现 db.collection(...) 业务读写。
  • groupApi 至少提供：bootstrap、getPublicGroup、createGroup、listMyGroups、updateGroup、createInvite、previewInvite、acceptInvite、revokeInvite、listMembers、removeMember。
  • shopApi 至少提供：listPublicShops、listPublicMapShops、listMemberShops、createShop、updateShop、deleteShop。公开读取先验证 publicId 对应 active/public_read 清单；写操作必须验证有效成员和角色。
  • getPublicGroup、listPublicShops 和 listPublicMapShops 允许访客调用，但只返回公开清单名称及脱敏店铺 DTO，不返回成员、添加者、内部 groupId 或邀请信息。
  • 列表默认按 updatedAt desc, _id desc 游标分页，每页最多 20 条；服务端限制客户端传入的 limit，不能用无限制 skip 扫描。
  • 地图数据经公开只读云函数分页读取当前清单全部成员添加的店铺，不能按当前用户过滤或假设一次 get() 返回全部；在 200 家容量内必须全部渲染。
  • 新增的 groupId、创建者、角色和时间全部由服务端根据成员关系写入；更新只改变白名单字段，禁止把客户端传来的完整对象直接回写。
  • 列表请求需要防止竞态：切换清单、分类或页面销毁后，旧请求结果不得覆盖新清单数据。
  • 创建清单与 owner 成员、接受邀请与使用次数更新必须使用事务或可靠幂等补偿；并发加入不能超过人数上限。
  • 数据库规则验收必须证明：客户端 SDK 直接 get/add/update/remove 全部失败，只有通过云函数且权限正确的请求成功。
